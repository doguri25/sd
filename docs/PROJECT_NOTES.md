# 개발 · 패키지 구성 메모

## 변경 범위

이 패키지는 게임 기능 업데이트가 아니라 저장소·배포용 구성입니다. `index.html`은 입력받은 `samguk_dodgeball_atlas_v9.html`과 바이트 단위로 동일합니다. 원본 및 배포 파일 해시는 `package-info.json`에 있습니다.

게임 HTML을 나중에 수정하면 해시는 당연히 달라집니다. 그때는 코드 변경을 확인한 뒤 `package-info.json`의 게임 버전·패키지 버전·해시·변경 여부를 갱신합니다.

## 단일 HTML 구조를 유지한 이유

원본은 `<style>`, 캔버스·SVG 생성 코드, Web Audio 효과음, 장수·지도·상점 로직을 한 파일 안에 포함합니다. GitHub Pages 배포를 위해 이를 억지로 분리하거나 번들러를 도입하지 않았습니다. 추가 `npm install`이나 빌드 단계가 없습니다.

`data/world-v9.json`은 기존 ZIP에 들어 있던 참고 데이터의 복사본입니다. 현재 런타임에서 가져오는 외부 설정 파일이 아닙니다. `data/`만 바꿔서 업데이트했다고 착각하지 않도록 주의합니다. 장수·규칙 변경은 실제 `index.html`의 데이터와 코드에도 반영해야 합니다.

`assets/screenshots/`는 기존 v9에서 제공된 실제 게임 화면입니다. 이번에 새로 생성한 게임 장면이나 필수 런타임 스프라이트가 아닙니다.

## 경로와 배포

게임 실행에 루트 절대 경로를 가정하는 외부 리소스가 없어서 프로젝트 사이트의 `/저장소명/` 하위 경로에서도 독립 실행하도록 구성되어 있습니다. README·문서·스크린샷 링크는 상대 경로입니다.

`.nojekyll`을 포함하고 브랜치의 루트에서 정적 배포합니다. 사용자 정의 도메인, 리디렉션, 계정명, 인증 토큰은 넣지 않았습니다. `CNAME` 또는 사용자를 대신하는 저장소 원격 주소도 미리 만들지 않았습니다.

## 저장 키와 업데이트 주의

원본 호환성을 위해 다음 저장 키를 변경하지 않았습니다.

```text
samguk_action_sound
samguk_warlords_v7_profile
samguk_warlords_v9_conquest
samguk_warlords_v8_conquest  (이전 점령전 불러오기용)
```

같은 출처(origin)에 같은 게임의 여러 버전을 올리면 이 키를 공유할 수 있습니다. GitHub 프로젝트 사이트는 저장소마다 URL 경로가 달라도 같은 계정의 `github.io` 출처를 공유할 수 있으므로, 실험용 버전과 실제 운영 버전을 동시에 사용할 때는 기록 파일을 백업하세요. 향후 저장 키에 버전별 접두사를 추가하려면 기존 기록 마이그레이션도 함께 구현해야 합니다. 출처별 저장 방식은 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)을 참고하세요.

정적 게임이므로 군공·점령전은 브라우저 측에서 저장됩니다. 사용자 계정 간 동기화, 온라인 대전, 서버 검증 랭킹은 구현되어 있지 않습니다. 배포했다고 이런 기능이 자동으로 생기지 않습니다.

## 공개 저장소 점검

게임 실행에는 비밀번호·API 키·개인 저장 파일이 필요하지 않습니다. `.gitignore`에 로컬 기록·환경 파일·임시 파일 제외 패턴을 넣었으나, 이미 Git이 추적 중인 파일이나 직접 선택한 웹 업로드 파일까지 보호하는 장치는 아닙니다.

개인 경기 기록·학생 정보·계정 정보는 패키지에 포함하지 않았습니다. 새로 자료를 추가할 때에도 공개될 내용인지 직접 확인합니다.

폰트 파일은 포함하지 않았고 원본의 시스템 글꼴 이름만 유지합니다. 라이선스는 이번 패키징에서 임의로 부여하지 않았습니다.

## 확인 도구

`python tools/check_package.py`는 필수 파일, 로컬 문서 링크, JSON 형식, 게임 버전, 원본 해시, 외부 실행 리소스 유무를 확인합니다. Node.js가 있으면 `node --check`로 인라인 스크립트 문법을 확인합니다. 네트워크 접속이나 패키지 설치는 하지 않습니다.

이번 브라우저 실행 검증의 범위와 한계는 [PACKAGE_CHECKS.md](PACKAGE_CHECKS.md)에 있습니다. `index.html`을 수정한 뒤에는 게임 실행·점령전·파일 저장/불러오기 등을 따로 확인해야 합니다.
